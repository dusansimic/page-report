🚀 CLI Plan Download Feature

Objective: Add ability for users to download previously uploaded plan HTML files from the page-report service via CLI.

📋 Feature Overview

Extend the pr CLI with a download command to retrieve published plan files by ID or name, enabling agents to programmatically fetch their previous outputs without web UI access.

Component Current State Change Required
CLI Upload-only (upload.go) Add download.go command
Proto API CreatePage RPC only Add GetPage RPC
Server Page storage + serving Expose GetPage handler
Database pages table exists Verify ID/name queries

🔧 Implementation Phases

Phase 1: Proto Contract (30min)

  • Define GetPageRequest message (id + optional name_pattern)
  • Define GetPageResponse message (id, name, content, created_at, mime_type)
  • Add rpc GetPage to PageReportService
  • Run buf lint && buf generate
  • Commit: feat(proto): add GetPage RPC for plan download

Phase 2: Server RPC Handler (45min)

  • Implement GetPage handler in internal/server
  • Query store by ID or name pattern
  • Auth check via bearer token (existing validator)
  • Return page content + metadata
  • Error handling: not found, unauthorized
  • Commit: feat(server): implement GetPage RPC handler

Phase 3: CLI Command (30min)

  • Create cmd/pr/download.go (cobra Command)
  • Flags: --id, --name, --output (default: stdout or file)
  • Connect to server using existing client config
  • Call GetPage, write to disk/stdout
  • Error output to stderr, exit codes
  • Commit: feat(cli): add download command for plan retrieval

Phase 4: Tests & Docs (1h)

  • Write server integration tests
  • Write CLI e2e test (upload → download → compare)
  • Update README with download usage
  • Update AGENTS.md with pr tool docs
  • Commit: test(download): add integration + e2e tests

📐 Architecture Details

Proto Changes

rpc GetPage (GetPageRequest) returns (GetPageResponse) {}

message GetPageRequest {
  string id = 1;              // page UUID (required)
  string name_pattern = 2;    // optional: filter by name prefix
}

message GetPageResponse {
  string id = 1;
  string name = 2;
  bytes content = 3;          // HTML binary
  google.protobuf.Timestamp created_at = 4;
  string mime_type = 5;       // "text/html" usually
}

Server Handler Signature

func (s *Service) GetPage(ctx context.Context, req *connect.Request[pagereportv1.GetPageRequest]) (*connect.Response[pagereportv1.GetPageResponse], error)

CLI Usage Examples

pr download --id abc123                      # stdout
pr download --id abc123 --output plan.html    # to file
pr download --name my-plan --server localhost:8080  # custom server

⚠️ Design Decisions

  • Query by ID (primary): Stable, performant, no ambiguity.
  • Name pattern (secondary): Optional convenience for humans; server returns latest match.
  • Auth: Reuse existing bearer token from internal/client; same as upload flow.
  • Output: Default stdout (for piping); --output flag for files. Preserves UNIX philosophy.
  • Store query: Leverage existing SQLite schema; no migration needed if id + name indexed.
